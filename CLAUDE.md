# confluence-rag-modding — working guide

A **pull-aggregator** knowledge base. Five modding repos are the canonical sources; this repo
holds a metadata-stamped copy of their documentation, shaped for a future Confluence sync and a
future RAG vector store. Read `README.md` for the layout and `curated/overview.md` for what is
where.

## Rules

1. **`docs/` is generated. Never edit it.** If a synced document is wrong, fix it in the source
   repo (the `source_repo` / `source_path` in its frontmatter say where), then run the sync.
2. **Routing lives only in `sources.json`.** Adding, moving, renaming, retagging or excluding a
   document is a manifest change plus a sync, never a hand edit under `docs/`.
3. **Hand-written material goes in `curated/`.** Give each file the minimal frontmatter block the
   existing curated docs use (`id`, `title`, `section`, `game`, `kind: "curated"`, `tags`) so the
   future consumers can treat curated and synced docs uniformly.
4. **Never change a source repo's branch from here.** The sync reads whatever is checked out and
   records the branch and commit per document. If a source is on a feature branch, say so in the
   sync commit message.
5. **`python tools/sync.py --check` before committing.** Commit `docs/` together with the
   `sources.json` change that produced it. Review the "Unresolved links" and "Duplicate-copy
   checks" sections of `docs/INDEX.md` after every sync.
6. **`tools/sync.py` stays stdlib-only Python.** The RAG pipeline will be Python too; keep zero
   dependencies so the corpus can be rebuilt anywhere. `tools/sync.ps1` is only a wrapper.
7. **LF, UTF-8, no BOM** everywhere (`.editorconfig`, `.gitattributes`). The sync normalises what
   it reads and writes LF explicitly.
8. **Don't fold the future in early.** `confluence/` and `rag/` hold design notes, not code. Build
   those tools when asked, as separate tools that read `docs/catalog.json` and the frontmatter.

## Map

```
sources.json               manifest: source repos, ordered mappings, duplicate checks
tools/sync.py              the sync (see tools/README.md for flags and manifest fields)
tools/sync.ps1             PowerShell 5.1 wrapper
docs/                      GENERATED corpus; INDEX.md and catalog.json are its indexes
curated/                   overview, glossary, repos — hand-written
confluence/README.md       how the page tree, titles and ids are meant to map
rag/README.md              how chunking, metadata and filtering are meant to work
.claude/skills/sync-docs   the /sync-docs skill: check → sync → review → commit
```

## Conventions carried over from the source repos

- Single `#` H1 per document, usually `Name — subtitle`; a thesis paragraph before the first `##`.
- Inline confidence marks: `[verified]` (measured here), `[community]` (established lore, not
  re-tested), `[unverified]`, `[upstream]` (from tool/game source), `[author]` (a mod author's
  claim). Never upgrade a mark without evidence.
- Generated files announce themselves on line 1 (`<!-- GENERATED by … -->`) or in a leading
  blockquote (`> **Generated** by …`, `> Auto-generated by …`). The sync detects both.
- Folder-level `README.md` files are index tables and become the parent page in Confluence.

## Duplicate copies

`skyrim-record-patterns.md` and `mod-dev-workspace-prompt.md` are byte-identical in several
repos; only oculory's copy is synced. enderal-mods' `arch-docs/enderal/` and `arch-docs/EGO/` are
newer than zenderal-patches' copies and are the ones synced. The sync checks every skipped copy
against its canonical and warns when one that should be identical has drifted. If that warning
appears, reconcile the source repos; do not add a second mapping.
